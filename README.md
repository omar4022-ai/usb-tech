# موقع USB TECH

موقع تعريفي مبني باستخدام React وTypeScript وVite، بالعربية والإنجليزية، مع خط Cairo ووضعين ليلي وفاتح. ترتيب الأقسام: الرئيسية، خدماتنا ونماذجها، من نحن، كيف نعمل، ثم تواصل معنا. تجمع كل بطاقة وصف الخدمة ومعاينتها وزر فتحها، دون أقسام شرح مكررة. يقود زر المقدمة إلى الخدمات، ويمكن طلب حل مشابه من داخل النموذج.

يفتح زر «افتح النموذج» أو الضغط على صورته نظامًا تفاعليًا بصفحات حسب الوظائف، مع أولوية للهاتف. النماذج تُحمّل عند فتحها لتقليل تحميل الصفحة الرئيسية.

| النموذج | ما يمكن تجربته |
| --- | --- |
| منظومة الأعمال | مركز معاملات توضيحي مستوحى من الجهات الخدمية: دليل عملي لإنشاء معاملة كموظف، تدقيقها كمراجع ثم اعتمادها كمدير. شرح مبسط للأدوار والصلاحيات، فتح مباشر للتفاصيل، وسجل يوضح من فعل ماذا ومتى، مع السجلات والتقارير. |
| موقع الشركة | شركة «مدار للحلول»: الرئيسية، من نحن، الخدمات، تصورات مشاريع، ونموذج طلب متحقق مع ملخص محلي. |
| المتجر | كتالوج وصور iPhone 18 Pro Max، بحث وتصنيفات وترتيب، اختيار اللون والسعة، سلة، إتمام طلب تجريبي، وتتبع المراحل. |
| مساعد المبيعات | محادثة موجهة تستخدم منتجات الكتالوج نفسه: إجابة مباشرة عن السعر والتوفر، ثم اختيار السعة واللون والكمية والاستلام والبيانات، وصولًا إلى ملخص قابل للمراجعة. |
| الفندق | واجهة ضيف للبحث والحجز، وواجهة موظف للحجوزات والتقويم والإشغال؛ تحقق من التداخل والسعة، وصول ومغادرة وإلغاء. |
| المطعم | «رِواق»: قائمة مصوّرة، إضافات وملاحظات، سلة، طاولة/استلام/توصيل، حجز طاولة، ثم مطبخ وتتبع ودوْر مدير/مطبخ/صندوق وتقارير وتوفر الأصناف. |

الواجهات تعمل بالعربية والإنجليزية والوضعين الليلي والفاتح. تغيير اللغة أو التنقل داخل النموذج يحافظ على حالته أثناء فتحه. واجهتا العميل والموظف في الفندق والمطعم تتشاركان بيانات التجربة نفسها. التغييرات محلية وتُعاد تهيئة النموذج عند إغلاقه وفتحه مجددًا؛ لا مشتريات أو حجوزات أو رسائل حقيقية، ولا تسجيل دخول أو تخزين خادم أو تحصيل مالي. صلاحيات الموظفين تحكم عمليات الواجهة التجريبية، وليست نظام مصادقة للإنتاج.

المتجر ومساعد المبيعات يشتركان في تعريف المنتجات والأسعار والمخزون الابتدائي في `src/components/demos/store-catalog.ts`. الأسعار والمخزون توضيحيان؛ حركة طلبات المتجر محلية داخل نموذج المتجر. مساعد المبيعات يستخدم قواعد محادثة محلية، ولا يتصل بنموذج ذكاء اصطناعي أو واتساب.

تُحمّل الصور من `public/demo-store` و`public/demo-operations` و`public/demo-identity`، ومراجعها موثقة داخل المجلدات. صور iPhone من Apple. استُفيد من تدفق القائمة والتصنيفات والإضافات والسلة في [مرجع المطعم](https://ilcaffe-italiano.imenu.ly)، مع اسم وهوية ونصوص مستقلة، دون ربط أي طلبات بالنشاط المرجعي.

على الهاتف تصبح النماذج بملء الشاشة، مع شريط تحكم مختصر، مدخلات 16px، وأهداف لمس لا تقل عن 44px. القوائم والبطاقات تتكيف مع العرض الضيق، وتقويم الفندق فقط له تمرير أفقي محصور وواضح. اختُبر فتح النماذج الستة والعودة منها، وتمرير الخدمة إلى نموذج التواصل، والعرض بالعربية والإنجليزية على الهاتف.

## النشر على GitHub Pages

ملف `.github/workflows/deploy-pages.yml` يبني الموقع وينشر `dist` عند تحديث فرع `main`، ويمكن تشغيله يدويًا من Actions. اختر **GitHub Actions** كمصدر في إعدادات المستودع ضمن **Settings → Pages** قبل أول نشر.

تستخدم إعدادات Vite ومسارات الصور عناوين نسبية، ليعمل البناء على مسار المستودع مثل `/usb-tech/` أو على نطاق مستقل. لا تضف اسم المستودع يدويًا إلى روابط الصور. ملف إعدادات الموقع هو `src/config/site.ts`.

## التشغيل والمعاينة

نفّذ الأوامر التالية من مجلد `usb-tech-site` بعد توفر Node.js وnpm:

```sh
npm install
npm run dev
```

افتح [المعاينة المحلية](http://127.0.0.1:4173). يظهر العنوان الفعلي في الطرفية؛ قد يختار Vite منفذًا آخر إذا كان 4173 مشغولًا.

لبناء ملفات الإنتاج في `dist`، مع فحص TypeScript، ثم معاينتها محليًا:

```sh
npm run build
npm run preview
```

تستخدم معاينة الإنتاج المنفذ 4173 أيضًا؛ أوقف خادم التطوير أولًا إذا أردت استخدام المنفذ نفسه. أمر البناء لا ينشر الموقع.

على هذا الجهاز، إذا لم يكن `npm` موجودًا في `PATH`، يمكن استخدام النسخة المتاحة في المجلد المجاور عبر PowerShell:

```powershell
node '..\.tools\npm\package\bin\npm-cli.js' install
node '..\.tools\npm\package\bin\npm-cli.js' run dev
```

استخدم المسار نفسه مع `run build` أو `run preview` عند الحاجة.

## فحوص النماذج

الاختبارات المحلية لا تحتاج متصفحًا أو خدمة خارجية:

```sh
node --test tests/*.test.mjs
```

تشمل فحوص انتقال الطلب بين الموظف والمراجع والمدير، وعدم تجاوز الصلاحيات، ومسار محادثة المبيعات وفهم المنتج والسعة والكمية، وتصيير الواجهات بالعربية والإنجليزية.

## الإعدادات المركزية

عدّل القيم في `src/config/site.ts`:

| المفتاح | الاستخدام |
| --- | --- |
| `facebookUrl` | رابط صفحة USB TECH الكامل على فيسبوك بصيغة HTTPS. |
| `contactEmail` | بريد التواصل الفعلي. |
| `phone` | رقم الاتصال المباشر؛ القيمة الحالية `+218922221113`. |
| `whatsappNumber` | وجهة محادثة وطلبات واتساب؛ القيمة الحالية `218922221113` بأرقام دولية فقط دون `+` أو مسافات. |
| `logoUrl` | مسار الشعار؛ القيمة الحالية `./usb-tech-logo.png`. |
| `formEndpoint` | عنوان خدمة استقبال الطلبات؛ عند تركه فارغًا يُجهَّز الطلب لواتساب إذا ضُبط رقمه، وإلا تظهر معاينة محلية فقط. |

اترك بيانات التواصل غير المتوفرة فارغة. الشعار الأصلي ذو الخلفية الشفافة موجود في `public/usb-tech-logo.png`. المحتوى المترجم للخدمات وخطوات العمل موجود في `src/content.ts`.

لتفعيل فيسبوك، ضع الرابط الحقيقي مثل `https://www.facebook.com/YOUR_PAGE` في `facebookUrl` بعد استبدال `YOUR_PAGE` بالصفحة الفعلية. يستخدم زر «تابعنا على فيسبوك» / “Follow us on Facebook” وأيقونة التذييل القيمة نفسها. يظهران عند ضبط رابط صالح للصفحة، ويختفيان عندما تكون القيمة فارغة أو غير صالحة. يفتح كلاهما تبويبًا جديدًا باستخدام `target="_blank"` و`rel="noopener noreferrer"`.

تغيير الإعدادات ينعكس في معاينة التطوير. لتحديث أي نسخة مستضافة، أعد البناء وانشر ملفات الإنتاج المحدثة.

## طلبات واتساب وربط الإرسال

الإعداد الحالي يجهّز الطلب لواتساب على الرقم `+218922221113`: يتحقق النموذج من الحقول، ثم يعرض ملخصًا للمراجعة ورابطًا لفتح الرسالة في واتساب. **يجب أن يضغط الزائر «إرسال» داخل واتساب حتى تصل الرسالة**؛ فتح المحادثة وحده لا يرسلها، ولا يعرض الموقع تأكيد استلام. يمكن نسخ نص الطلب كاملًا أيضًا، لاستخدامه عند تعذّر ملء الرسالة تلقائيًا.

يتشارك رابطا واتساب في قسم التواصل والتذييل ونموذج الطلب قيمة `whatsappNumber` نفسها. عند إفراغ رقم واتساب وترك `formEndpoint` فارغًا، يعود النموذج إلى معاينة محلية دون إرسال. تبقى البيانات أثناء تغيير اللغة أو العودة من واتساب، ولا تُخزّن الطلبات على خادم الموقع.

لتفعيل إرسال مباشر عبر خادم بدل تجهيز رسالة واتساب، جهّز خدمة عبر HTTPS ثم ضع عنوانها في `formEndpoint`؛ هذا المسار له الأولوية عند ضبطه. يرسل النموذج طلب `POST` بترويسة `Content-Type: application/json` وبنية البيانات التالية:

```json
{
  "name": "اسم العميل",
  "business": "اسم النشاط أو نص فارغ",
  "contact": "البريد الإلكتروني أو رقم الهاتف",
  "service": "company",
  "brief": "نبذة عن المشروع",
  "language": "ar"
}
```

قيم `service` هي `company` و`identity` و`store` و`automation` و`hotel` و`restaurant`، بالترتيب المعروض في الموقع. قيمة `language` هي `ar` أو `en`. حقل `business` اختياري، وبقية بيانات الطلب مطلوبة.

لا تعرض الواجهة نجاح الإرسال إلا عند استجابة HTTP ضمن نطاق `2xx` تحتوي JSON بالقيمة المنطقية التالية، بعد استلام الطلب الحقيقي:

```json
{ "success": true }
```

الاستجابة الفارغة أو غير المطابقة تُعامل كفشل، وكذلك انتهاء مهلة الطلب بعد 20 ثانية. تبقى بيانات النموذج عند الفشل وعند تغيير اللغة أو المظهر.

على خدمة الخادم:

- تحقّق من الحقول وأطوالها وصيغها والخدمة المختارة، وطبّق حدودًا لمعدل الطلبات.
- عند استخدام نطاق مختلف، اضبط CORS للسماح بأصل الموقع وطلبات `POST` والترويسة `Content-Type`، وتعامل مع طلبات `OPTIONS` التمهيدية.
- احفظ مفاتيح البريد أو الخدمات الخارجية وأي أسرار في بيئة الخادم فقط. ملف `src/config/site.ts` وملفات الواجهة عامة ويستطيع الزائر الاطلاع عليها.
